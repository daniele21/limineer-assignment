> ## Conservative evidence policy
>
> Every observation records its actor, scope, statement status, evidence basis,
> source note ID and exact quote. Qualifications and approximate quantities remain
> visible. All dated observations are preserved; Claude does not pick the current
> state or decide that reported reserve overlap is a confirmed exclusion.
>
> Following the existing prompt, **absent evidence means no observation**, so the
> fact remains unknown. Explicit uncertainty in the text can yield an observation
> with value `unknown`, `conditional` or a qualified claim. No observation never
> means neutral, zero, false, or no risk. Qualified claims are not confirmed facts.
> This slice does not turn observations into final scoring signals yet.
>
> Code rejects an observation if its note ID or exact quote is invalid, its value
> violates the kind's allowed labels, its event timing is not quoted, or a required
> quantity is absent or invalid. Numeric quantities must be finite and nonnegative;
> units are retained as written rather than converted. Invalid observations are
> removed and explained in `validation_issues`. Owner sentiment cannot become
> community sentiment. Empty notes produce an empty array without an API call.
>
> Quote matching proves provenance, **not semantic correctness**. Actor attribution,
> qualifications, and evidence basis explain the grounds for the claim, but a human
> sample review remains necessary before these outputs drive scores. No model
> confidence number is used as proof. The API uses Anthropic's
> [structured-output SDK helper](https://platform.claude.com/docs/en/build-with-claude/structured-outputs).
> Refused, truncated and misattributed responses fail the run. The SDK retries
> transient API errors up to twice.
